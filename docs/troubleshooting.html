Problem solving

Troubleshooting

Start with the symptom below. Change one setting at a time and test with one instance whenever possible.

Check compatibility first. PTCGPB, the SpeedMod or other APK mod, the Ready2Go image, MuMuPlayer and Pokémon TCG Pocket change independently. Confirm that the versions you use are intended to work together before copying old patches or changing advanced settings.

Startup and windows

PTCGPB closes or asks for administrator permission
PTCGPB requires administrator permission. Launch it again and approve the Windows prompt. If the prompt never appears, right-click the script and choose the administrator launch option.
Windows asks which program should open PTCGPB.ahk
Install AutoHotkey v1.1. PTCGPB uses AutoHotkey v1 syntax and cannot be run with AutoHotkey v2 alone.
PTCGPB behaves incorrectly from its current folder
Check the complete folder path. It must not contain spaces. Move the entire bot folder to a path such as C:\PTCGPB and launch it again.
Launch All MuMu does nothing
Confirm that the latest MuMuPlayer is installed. Open Tools & System and verify the automatically detected MuMu Folder Path. Make sure you named your instances correctly.
The bot repeatedly restarts on a white screen
Start Pokémon TCG Pocket manually without the bot. If the game works but PTCGPB continues waiting and restarting, update MuMuPlayer and test a fresh Ready2Go instance. If that still fails, back up account data and perform a clean MuMuPlayer reinstall.
MuMu reports “Operation terminated” or requests another rendering mode
Try the requested rendering mode, but update MuMuPlayer if the error returns. This can appear after a GPU driver change even when the previous mode had been working.
PTCGPB reports an “Invalid Port” error
Make sure the instance is running, try Launch All MuMu, verify the configured MuMu folder and confirm that numbered instances have no naming gaps. If Launch All MuMu also fails, investigate path or instance detection before the port itself.
PTCGPB reports a missing or blocked helper program
Keep Helper\carddb.exe and Helper\cardimage.exe with the rest of the release. PTCGPB tests and attempts to unblock both at startup. If either file is missing, extract a complete release again. If Windows still prevents it from starting, check antivirus quarantine before asking for help in Discord.
An instance is not recognized or arranged
In MuMu Multi-Instance Manager, rename numbered instances exactly 1, 2, 3, and so on. Do not leave numbering gaps. Name Main instances Main, Main2, etc. Confirm the Instances and Mains counts match.
The computer slows down or freezes during startup
Reduce Instances and test with one. Increase Instance Start Delay for bot scripts and Launch MuMu Delay for emulator windows. Add instances gradually after a complete successful run.

Clicks, swipes and navigation

The bot clicks the wrong location
Use 100% or 125% Windows display scaling while testing, select Arrange, and make sure every MuMu window has the same size and layout. Verify that No Speedmod Menu Clicks matches whether your APK provides the speedModMenu.
The bot is stuck on “Tap to Start”
Verify emulator resolution and DPI, run Arrange, check the SpeedMod setting and undo recent emulator display, FPS or layout changes. If the Ready2Go instance was modified manually, import a clean copy and test one instance.
The bot clicks before a screen finishes loading
Increase Delay above the default 250 ms. Small increments are easier to evaluate. Network and PC load can require a larger delay.
Swipes are missed or stop short
Adjust Swipe Speed in small steps. Confirm whether you use the speedModMenu and follow the matching recommendation shown in the in-app tooltip.
The bot clicks speed buttons that are not present
Enable No Speedmod Menu Clicks under Tools & System when using the base game without the speedModMenu. Leave it disabled when using the speedModMenu.

OCR and card recognition

Text or card recognition is unreliable
Set Client to the language used inside the game. Set OCR to the corresponding Windows OCR language; using the same Windows display language gives the best result. Reduce the run to one instance while testing.

Friends, Main and groups

Friend requests do not reach Main
Check that Friend ID contains exactly 16 digits without spaces or dashes. Verify the Main MuMu instance is named Main. Increase Wait Time if acceptance cannot complete before numbered instances continue.
Automatic GP tests remove friends too early
Increase GP Test Wait above the default 150 seconds. Confirm numbered instances can remove their friends before Main begins removing non-VIP friends.
Shared Friend IDs are not downloaded
Verify the ids.txt API URL with the group administrator and check that it returns a plain Friend ID list. Do the same for vip_ids.txt. Do not replace group URLs with ordinary Discord page links.

Accounts and files

An Inject mode finds no eligible accounts
Confirm saved XML files exist and are distributed to the numbered instance folders. Eligibility also depends on timestamps, pack counts, flags, used status and bot mode. Normal pack injection requires at least 24 hours after the last recorded pack pull; Wonderpick also applies Min Packs. Open Injection Queue in Cockpit to inspect ready and cooling accounts before changing Sort By or using Force inject.
Inject Rewards finds no accounts for a new event
Confirm Claim Rewards is enabled and that the intended active .sevt file exists under SpecialEvents\Events. Current versions track claim counts per event, so a routine global Claim Status reset is not required. Reset only when you intentionally need to clear stale or incorrect event progress.
Inject 13P+ or Inject Rewards repeatedly restarts or fails
Check PTCGPB and mod/APK compatibility first. If the failure occurs around a SpeedMod step, test a fresh, complete bot folder instead of continuing to repair a mixed installation. Copy back only the required account data and test one instance.
An old account stops on a “Welcome Back” screen
Accounts inactive for roughly two weeks may receive extra Welcome Back screens and missions. Use a current, compatible PTCGPB version that supports the popup, missions and related reward screens. Current versions dismiss the pre-claim screen during reward claiming and recognize both supported Welcome title-screen variants. If the flow still stops, save a screenshot and check that the game, mod/APK and PTCGPB release are compatible.
Force inject skips accounts on a later run
Force injection is intentionally limited to one pass per account. Select Clear force inject flags on the main window to allow another forced pass.
Accounts are unevenly distributed
Stop the bot, set the correct Instances count and use Balance XMLs.
You suspect duplicate XML accounts
Back up both account-data folders first, then open Tools & System and run XML Duplicate Remover. It keeps the copy with more packs or the older copy.

Discord

No messages arrive
Check that the feature itself is enabled, its specific webhook field is populated and the webhook still exists in Discord. Solo, Group, Save for Trade and heartbeat each use separate destinations.
A webhook was posted publicly
Delete that webhook in Discord immediately, create a new one and replace the value in PTCGPB. Removing a screenshot or message is not enough because the old URL may already have been copied.

Updates

The bot stopped working after an update
Confirm the exact PTCGPB, mod/APK, Ready2Go and MuMuPlayer versions. Mixed files from different releases commonly cause failures. If older scripts, ADB files, patches or mod files were copied into this installation, test a completely fresh bot folder and restore only the account data you need.
No releases appear in Version Manager
Confirm the PC can reach GitHub, choose the intended stable or beta channel, and select Save & Refresh. Stable hides prereleases; prerelease builds automatically use beta.
An update cannot be installed
Do not replace files manually while PTCGPB is running. A failed checksum, invalid release manifest, failed pre-update backup, or a Card Database helper that cannot be stopped will stop installation. Close carddb.exe and cardimage.exe, then retry. Keep the displayed error and backup path when asking for support.

Collect useful information for support

  1. Reproduce with one instance

    Record the selected bot mode and the last visible screen before the problem.

  2. Temporarily increase logging

    Switch Log Level from info to debug. Use trace only when necessary.

  3. Remove secrets

    Redact Friend IDs, webhook URLs, Discord IDs and account XML contents from screenshots and logs.

  4. Restore normal logging

    Return to info after collecting the relevant information.

What to include when asking for help

  • Exact PTCGPB, mod/APK, Ready2Go, MuMuPlayer and Android versions.
  • Bot mode, instance count and Windows display scaling.
  • A screenshot or short video showing the settings, last successful screen and displayed instance status.
  • Whether the game works manually, whether one or every instance is affected, and what changed before the issue.
  • Debug logs from a one-instance reproduction. Remove webhook URLs, Friend IDs, Discord IDs and account XML contents before sharing.
Safe troubleshooting order: Verify compatibility → restart → check layout and emulator settings → test one instance → try a fresh bot folder → try a fresh Ready2Go instance → reinstall MuMuPlayer. Back up account data before replacing anything.
