Frequently asked questions

Explanations of account data, injection behavior and event tracking. For a bot or emulator failure, start with Troubleshooting.

Accounts and metadata

Can I move my reroll accounts to another installation or PC?
Yes. Copy Accounts\Saved for the account login XMLs and Accounts\Cards\accounts for metadata and recorded card history. XMLs remain usable without the metadata, but some stored information may need to be rebuilt. See Accounts and trading.
What does Force inject do?
It bypasses normal Inject-mode eligibility once per account. It is useful for troubleshooting stale or incorrect metadata, but normally does not need to remain enabled. PTCGPB records an FI flag when the account is claimed. Use Clear force inject flags before another forced pass.
Some XML files have random alphanumeric names. Is that broken?
No. Newer files can be named from the account or device identifier. Descriptive information is stored in Accounts\Cards\accounts. Do not manually rename the JSON metadata files.
Why does an account show 0 packs?
Zero can mean the metadata does not yet contain a known pack count. The bot may inject the account to determine the actual value and then update the metadata; zero does not by itself mean that the account is broken or empty.
The JSON metadata exists but the XML is missing. Can I recover the account?
Generally not. The XML contains the login data; JSON only describes the account. This is why Accounts\Saved must be backed up.

Event and reward tracking

Must I reset Claim Status after every event?
No. Current .sevt definitions track each event and its daily steps separately in account metadata. Reset Claim Status clears all of that progress and should be used only for recovery or an intentional replay. For an Elite Deck event, enable the extractor's Elite Deck option so PTCGPB restarts after claiming and registers the awarded cards.
